# AI 助手 · 产品需求文档（PRD）

版本：v1.0（规划稿）　归属：MySQL Web Studio　作者：guonl

---

## 1. 背景与问题

目标用户是使用本客户端的 DBA / 后端开发 / 数据分析人员。当前产品的痛点：

- **记不住结构**：库多表多，写 SQL 前要反复翻侧栏、看 DDL、猜列名；
- **门槛不均**：新手会写 `SELECT` 但不熟悉复杂 JOIN、窗口函数、执行计划；
- **排错成本高**：执行报错后只能自己读错误码查文档；
- **重复劳动**：相似的分析 SQL（按天聚合、找差异、生成测试数据）每次手写。

在客户端内置 AI 助手，让模型「看到」真实的库表结构，用对话完成生成、解释、优化、代查与受控代执行，把上述四类成本压到一次对话内。

## 2. 目标与非目标

**目标**

1. 配置一个 OpenAI 兼容端点后，3 分钟内跑通「问 → 生成 SQL → 运行 → 拿到结果」闭环；
2. Agent 能自主查元数据（库/表/结构/样本），减少用户来回贴表结构；
3. 任何非只读操作在默认配置下 100% 经过人工确认弹窗；
4. 全程纯前端，密钥与对话历史不出本机。

**非目标（本期不做）**

- 不做 RAG / 向量库 / 服务端网关（保持纯前端架构）；
- 不做多模态（图片、语音）；
- 不做团队共享配置与对话协作；
- 不做 SQL 的自动静默修复重试（重试必须用户可见）。

## 3. 用户与核心场景

| 场景 | 描述 | 依赖需求 |
| --- | --- | --- |
| A. 自然语言查数 | 「上个月每个分类的销售额 TOP5」→ AI 查表结构 → 生成 SQL →（确认/自动）执行 → 用中文解读结果 | FR-10/13/14/17 |
| B. 写不出复杂 SQL | 「帮我把这两个表按用户 ID 关联，找出只有记录没有用户的脏数据」→ AI 给出 LEFT JOIN + NULL 判断方案 | FR-08/09/10 |
| C. 看懂别人的 SQL | 选中编辑器中一段存储过程 / 大查询，`/explain` 得到逐段解释与风险提示 | FR-11 |
| D. 报错求助 | `Unknown column 'usr_id'` → 右键「让 AI 修复」，AI 查结构后指出应为 `user_id` 并给出修正 SQL | FR-23/13 |
| E. 变更脚本起草 | 「给 orders 表加一列 remark，写清迁移与回滚语句」→ AI 输出 ALTER + 回滚 SQL，用户确认后在测试库验证 | FR-09/16 |

## 4. 功能需求列表

优先级：**P0** = 首版必须；**P1** = 紧随其后；**P2** = 增强项。

### 4.1 模型接入

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-01 | **供应商配置**：OpenAI Chat Completions 兼容格式；可配置请求地址 baseURL、模型 ID、API Key；内置常见端点预设（OpenAI / DeepSeek / Moonshot / 通义 / Ollama 本地等，一键填入 baseURL） | P0 |
| FR-02 | **连接测试**：配置面板内「测试连接」按钮，发起一次最小请求（`max_tokens: 1`），反馈成功 / 鉴权失败 / 地址不可达 / CORS 受限四类明确结果 | P0 |
| FR-03 | **多配置管理**：保存多套配置并快速切换，标记当前生效项 | P1 |
| FR-04 | **高级参数**：temperature、max_tokens、超时时间、System Prompt 追加段 | P2 |

验收（FR-01/02）：未配置时输入框发送 → 引导打开配置面板；填错 Key 测试 → 给出「401 鉴权失败，请检查 API Key」而非裸错误。

### 4.2 入口与对话面板

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-05 | **AI 入口**：顶栏 AI 图标按钮（呼吸/脉冲动效，可在设置关闭）；打开时面板从右侧滑入 | P0 |
| FR-06 | **右侧对话面板**：与左侧栏对称的可折叠列（挤压 Workbench 而非浮层遮挡）；宽度可拖拽（260–520px）并持久化；顶栏显示当前模型名 | P0 |
| FR-07 | **未配置引导**：首次打开展示欢迎页 + 「配置模型」直达按钮 | P0 |
| FR-25 | **动效开关**：呼吸动画与打字机效果可关闭 | P2 |

### 4.3 对话核心

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-08 | **流式多轮对话**：SSE 流式输出、打字机渲染；可随时「停止生成」（Abort）；网络中断给出可重试错误条 | P0 |
| FR-09 | **Markdown + SQL 代码块操作**：渲染 Markdown（标题/列表/表格/代码）；每个 SQL 代码块带工具条——复制 / 插入当前编辑器 / 直接运行；非 SQL 代码块提供复制 | P0 |
| FR-10 | **上下文注入**：自动注入活动连接名、活动 Schema、该 Schema 表清单（名称 + 注释，上限 50）；支持 `@表名` 语法在发送时附带该表 DDL 与列注释；无活动连接时提示先连接 | P0 |
| FR-11 | **快捷指令**：输入 `/` 弹出指令菜单——`/explain` 解释选中的 SQL、`/optimize` 优化建议（含执行计划解读建议）、`/fix` 修复报错、`/ddl <表>` 表结构问答、自由问答 | P0 |
| FR-12 | **会话管理**：对话历史本地持久化（上限 200 条，可一键清空）；「新会话」重置上下文 | P0（多会话 P1） |
| FR-24 | **结果解读**：结果页签右键「让 AI 解读」，把列名 + 截断样本发给模型分析 | P2 |

验收（FR-09）：生成的 SQL 块一键「插入编辑器」后光标落在新 SQL 末尾且标签页标脏；「直接运行」走与手动执行完全相同的结果页签通道。

### 4.4 Agent 工具与受控执行（本产品差异化核心）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-13 | **元数据工具集**：暴露 `list_schemas` / `list_tables(schema)` / `describe_table(schema, table)`（DDL + 列注释）/ `sample_data(schema, table, n≤20)` 四个只读工具，模型按需调用 | P0 |
| FR-14 | **受控执行工具**：`run_query(sql, schema?)` 走现有 `Adapters` 通道；自动附加行数上限（复用顶栏 maxRows），结果以摘要（列名、行数、前若干行）回传模型 | P0 |
| FR-15 | **执行策略分级**（默认值可配）：L0 只读（SELECT/SHOW/DESC/EXPLAIN）→ 自动执行（可关）；L1/L2/L3（DML/DDL/服务器级）→ 永远人工确认；无法解析的语句按最高风险处理 | P0 |
| FR-16 | **执行确认弹窗**：完整 SQL 高亮展示 + 风险徽章 + 危险特征说明（如「UPDATE 未带 WHERE」）+ 按钮「执行一次 / 拒绝」；可选「本会话内允许执行相同语句」（默认关） | P0 |
| FR-17 | **结果回填推理**：工具结果作为 tool 消息回填，模型可继续调用工具直至给出最终答案；用户拒绝执行时同样回传「用户已拒绝执行该语句」 | P0 |
| FR-18 | **预算控制**：单次提问 Agent 轮次上限（默认 8）、工具调用次数上限（默认 12）、到达上限强制收尾并告知用户 | P0 |
| FR-21 | **中止与失败**：对话流式中止会同时取消未执行的下一步；工具执行失败将错误信息回传模型重试或解释 | P0 |

### 4.5 安全与隐私

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-19 | **SQL 风险分级器**：前端静态解析语句类型与危险特征，输出 L0–L3 等级与特征标签（详见 tech.md 矩阵） | P0 |
| FR-20 | **危险特征检测**：UPDATE/DELETE 无 WHERE、多语句、`INTO OUTFILE/DUMPFILE`、`LOAD_FILE`、`GRANT/REVOKE`、`KILL`、`SET GLOBAL`、DROP/TRUNCATE/RENAME 命中即标红 | P0 |
| FR-22 | **密钥与隐私**：API Key 存 localStorage（`mws.v1.ai.settings`），仅发往用户配置的 baseURL；配置面板展示隐私声明（不发遥测、不含密码、历史仅存本机）；Demo 演示连接可直接体验（只读工具可用，写操作按现有只读引擎拒绝并回传模型） | P0 |
| FR-26 | **Prompt Injection 缓解**：工具结果（表注释、数据内容）作为 tool 消息标注来源；模型输出永远只是「建议」，执行动作必须经本地风险分级与确认，不因数据内容改变权限 | P0 |

## 5. 非功能需求

- **兼容端点**：任何 OpenAI Chat Completions 兼容服务（含各主流国内供应商与 Ollama `http://localhost:11434/v1`）；CORS 不放行的端点给出明确提示与替代建议。
- **性能**：流式首字节渲染随网络；Markdown 渲染增量节流（≥60ms）；面板打开 < 100ms。
- **主题**：全部颜色使用现有 CSS 变量，9 套主题零适配。
- **体积**：新增第三方依赖仅 markdown 渲染（marked + DOMPurify，gzip 后约 +20KB），不引入 AI SDK 框架。
- **可维护**：AI 模块独立目录（`src/ai/` + `src/components/ai/`），对主工程仅 3 个挂载点（见 tech.md）。

## 6. 成功指标（上线后观察）

- 周活跃用户中 AI 面板使用率 ≥ 30%；
- 对话生成的 SQL 中「插入编辑器 / 直接运行」转化率 ≥ 40%；
- 确认弹窗拒绝率（健康信号：模型不该执行的被拦下）可观测但不设目标。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 目标端点不支持浏览器 CORS | 连接测试明确报「CORS 受限」；文档给出支持 CORS 的端点清单；架构预留 `AiTransport` 接口，后续可经本地桥接器/MV3 background 代理转发 |
| Token 成本失控 | 上下文最小化（表清单 ≤ 50、DDL 按需）、历史裁剪（200 条上限 + 超限摘要）、轮次/工具预算、max_tokens 可配 |
| Prompt Injection（恶意表注释/数据诱导执行） | 工具结果标注来源、执行必须过本地分级与确认、极高风险项永不自动执行、隐私声明告知用户 AI 输出仅为建议 |
| 用户误信 AI 删库 | 危险语句强制确认 + 徽章 + 特征说明；「会话内允许」默认关闭；建议文案提示先在测试库验证 |
