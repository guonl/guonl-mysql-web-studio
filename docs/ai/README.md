# MySQL Web Studio · AI 助手（Copilot）规划

> 一句话定位：把一个「读过你数据库结构」的 SQL Copilot 装进浏览器——用对话生成 SQL、解释与优化语句、按需代查元数据，并在受控、可确认的前提下代替用户执行操作。

本文档目录是 AI 助手功能的完整产品与技术规划，与仓库现有代码（React 18 + TS + Zustand + CodeMirror 6，纯前端架构）严格对齐。

---

## 设计原则

1. **数据不出本机**：模型请求由浏览器直连用户自配的 OpenAI 兼容端点；连接密码、数据内容不上传任何第三方，密钥仅存本地。
2. **AI 不能自己动手改库（默认）**：只有只读查询可被配置为自动执行；数据变更 / DDL / 未知语句一律弹窗人工确认，拒绝执行的结果会回传给模型。
3. **上下文按需最小化**：不把整库 DDL 灌给模型；默认只注入活动连接与 Schema 的表清单，表结构由 Agent 通过工具按需拉取，控 token 成本。
4. **与主产品同构**：复用现有 `DriverAdapter`、Modal 弹窗栈、SqlViewer、toast 与 CSS 主题变量——AI 面板在 9 套主题下零适配成本，功能上不绕过任何既有权限与安全边界。

## 核心用户旅程（预览）

```
用户：帮我看看 users 表结构，找出没有邮箱的用户
  │
  ▼ AI 调用工具 describe_table('users')          ← 面板内折叠卡片：「已查看 users 表结构」
  ▼ AI 流式输出分析 + SQL 代码块                  ← 代码块工具条：复制 / 插入编辑器 / 运行
  │
  ▼ 用户点击「运行」或直接让 AI 执行
  ▼ 风险分级：SELECT → L0 只读
  ├─ 策略=自动执行：直接执行，结果摘要回填对话，AI 继续总结
  └─ 策略=每次确认：弹出确认框（SQL 高亮 + 风险徽章）→ 用户确认/拒绝
  │
  ▼ AI 输出最终答案（含数据摘要与建议）
```

危险动作（`UPDATE` 无 `WHERE`、`DROP TABLE`、`GRANT` 等）在任何策略下都会强制弹窗，且徽章升级为高风险/极高风险提示。
