## 1. 连接管理

### 新建连接

1. 点击左侧栏顶部「**+ 新建连接**」按钮
2. 填写：
   - **连接名称**：自定义，用于在侧栏展示（如「本地开发」「测试库」）
   - **主机 / 端口 / 用户名 / 密码**：MySQL 服务器信息，端口默认 `3306`
   - **默认数据库**：可选，连接后默认使用的库
3. 点击「连接测试」验证，通过后「保存」

### 记住密码

- **勾选**「记住密码」：密码保存在本机浏览器 `localStorage` 中（明文），下次打开免输入
- **不勾选**：密码仅本次会话有效，刷新页面后需重新填写
- ⚠️ 请勿在公共电脑上勾选记住密码

### 高级选项

桥接地址通常**无需填写**：

- **Web 模式**：留空时自动使用当前页面同源的内置桥接器 `ws://{host}/__mysql_bridge`（随 `npm run dev` 启动）
- **Chrome 插件模式**：留空时自动连接本机独立桥接器 `ws://localhost:5189/__mysql_bridge`（需先运行 `npm run bridge`）
- **桌面客户端模式**：无需填写——连接类型默认「**桌面直连**」，主进程内置 mysql2 直连 MySQL，没有桥接器（「高级选项」整段隐藏）

仅当桥接器与页面不同源时（例如自建了独立桥接服务）才需要手动填写，格式必须以 `ws://` 或 `wss://` 开头（桌面客户端模式不存在此选项）。

### 连接操作

在左侧树的**连接节点**上右键：

| 菜单项 | 说明 |
| --- | --- |
| 打开连接 / 断开连接 | 建立 or 断开 WebSocket 桥接会话 |
| 刷新元数据 | 重新拉取 Schema / 表 / 视图列表 |
| 新建查询 | 用该连接打开一个新的查询标签页 |
| 新建 Schema… | 弹窗创建数据库（Schema），确认后执行 `CREATE DATABASE` 并自动刷新列表（仅已连接时可用） |
| 编辑连接 | 修改连接信息 |
| 删除连接 | 删除（红色危险项） |

## 2. 浏览数据库

左侧树为三级结构：**连接 → Schema（数据库）→ 表 / 视图**。

- **过滤**：顶部搜索框可按表名实时过滤当前 Schema 的表
- **新建 Schema（数据库）**：连接节点右键「新建 Schema…」，或 Schema 列表底部的「＋ 新建 Schema」入口。弹窗内填写名称（仅字母 / 数字 / 下划线 / `$`，上限 64 字符）、选择字符集与排序规则（按服务器大版本预选默认值，切换字符集时排序规则自动联动）、勾选 `IF NOT EXISTS`；底部实时预览将执行的 `CREATE DATABASE` 语句。创建成功后左侧树与顶部 Schema 下拉自动刷新。演示库为只读数据集，请在真实 MySQL 连接上使用
- **Schema 右键**：
  - 设为活动 Schema（当前查询标签页使用的库）
  - 在此新建查询
  - 新建表…（打开表设计器，见下文）
  - 刷新表
  - 复制名称
- **表右键**：

| 菜单项 | 说明 |
| --- | --- |
| 复制表名 / 复制全限定表名 | 复制 `table` 或 `schema`.`table` |
| 设计表… | 打开表设计器，可视化编辑列与索引并预览 / 执行 `ALTER TABLE`（视图禁用） |
| 查看 DDL | 弹窗展示 `SHOW CREATE TABLE` 结果（语法高亮，可复制 / 下载） |
| 最近 10 条记录 | 自动生成并执行 `SELECT * ... ORDER BY 主键/自然序 DESC LIMIT 10` |
| 查看前 100 行 | 执行 `SELECT * ... LIMIT 100` |
| 导出 SQL（DDL + 数据）… | 打开导出弹窗，见[导出](#7-导出) |
| 导出 CSV | 直接导出表数据为 CSV 文件 |
| 在新标签页查询 | 新开一个查询标签页 |

### 表设计器（Navicat 式可视化改表）

仿 Navicat 的表结构设计器：在表格网格中直接增删改列、管理二级索引，底部**实时预览**将执行的 SQL，确认后一键执行。

**入口**

- 修改表：表右键「**设计表…**」→ 弹窗加载现有列结构，标题显示 `设计表：schema.table`
- 新建表：Schema 右键「**新建表…**」→ 空白网格从零开始定义，标题显示 `新建表（schema）`

弹窗内有「**列** / **索引**」两个标签页，底部预览区对两个页签的改动统一实时生成 SQL。

**列网格（「列」标签页）**

每行一列，可直接编辑：

| 项 | 说明 |
| --- | --- |
| PK | 勾选为主键（可多列联合主键）；勾选「自增」会自动连带勾选主键 |
| 列名 | 支持 64 字符内的常规标识符 |
| 类型 | 下拉选择，按分组展示基础类型：**整数**（tinyint…bigint）、**小数**（decimal/float/double）、**字符串**（char/varchar/text 系/enum/set）、**日期时间**、**二进制 / JSON**；列表外完整定义（如 `int unsigned zerofill`）会自动保留显示 |
| 长度/值 | 独立输入框，按类型给出占位提示：`varchar` 填最大字符数、`decimal` 填 `M,D`、`enum`/`set` 填 `'a','b'` 值列表（缺失时保存前校验拦截）；text/blob/json/date 等不支持长度的类型自动禁用 |
| 无符号 | 勾选 = `UNSIGNED`，仅数值类型可用（tinyint…bigint、decimal/float/double 等）；与「长度/值」独立，改类型不再依赖 unsigned 组合项；已有 `unsigned zerofill` 的列取消勾选仅去掉 unsigned、保留 zerofill |
| 非空 | 勾选 = `NOT NULL` |
| 默认值 | 勾选后可填写。**留空 = 空字符串 `''`**（varchar 等字符列可直接得到 `DEFAULT ''`）；字符串值自动加引号（输入 `'abc'` 已带引号则原样使用）；`NULL` 需显式输入；`CURRENT_TIMESTAMP`、`NOW()` 等函数按表达式原样输出；数值列留空会被校验拦截（需填数字或 NULL） |
| 自增 | `AUTO_INCREMENT`（勾选时自动带上主键） |
| 注释 | `COMMENT` |

行操作：**上移 / 下移**调整列顺序（生成 ALTER 时以 `FIRST` / `AFTER` 落位）、**删除列**、「＋ 添加列」在末尾追加（新增行以淡色高亮标识）。

> **生成列**（`VIRTUAL/STORED GENERATED`）会自动识别并以半透明锁定展示——其 `AS` 表达式无法在网格中编辑，也不参与排序，避免生成损坏的 DDL。

**索引管理（「索引」标签页）**

管理表的**二级索引**（主键请在「列」页勾选 PK，不在此列）：

| 项 | 说明 |
| --- | --- |
| 索引名 | 常规标识符（不能为 `PRIMARY`，保存前校验） |
| 类型 | `INDEX` / `UNIQUE` / `FULLTEXT` |
| 索引列 | 多列用英文逗号分隔，如 `col1, col2`；支持前缀长度 `name(10)` 与 MySQL 8.0 表达式索引（`(json_extract(info,'$.x'))` 原样透传） |

- 修改表时自动从 `information_schema.STATISTICS` 加载现有索引（不含 PRIMARY），删除行 = `DROP INDEX`，修改名称或定义 = `DROP INDEX` + `ADD INDEX`，新增行 = `ADD INDEX`
- 生成 ALTER 时删除索引子句排在删除列之前，避免引用冲突
- 新建表时索引以 `INDEX / UNIQUE INDEX / FULLTEXT INDEX ...` 行内联进 `CREATE TABLE`

**新建表模式**

除列定义外还可设置：表名、存储引擎（InnoDB / MyISAM / MEMORY…）、字符集与排序规则（切换字符集时自动联动默认排序规则）、表注释、`IF NOT EXISTS`，以及索引标签页中的二级索引。

**SQL 预览与执行**

- 底部预览区实时显示将执行的完整 SQL：修改表为 `ALTER TABLE`（`ADD / DROP / MODIFY / CHANGE COLUMN` + 列重定位 + 索引增删改），新建表为 `CREATE TABLE`；上方的**改动摘要 chips** 逐条列出本次变更（如「新增列 memo」「新增索引 idx_user」）
- 列定义**不写列级 `CHARACTER SET` / `COLLATE`**（跟随表默认字符集，与 Navicat 默认行为一致），生成的 `ALTER` 更干净
- 点击「**保存改动…**」/「**创建表…**」弹出 SQL 确认窗：可**复制**全文或**下载** `.sql`，确认无误后点「**执行**」落库
- 执行成功后自动刷新左侧树与该表的列缓存、写入执行历史；执行失败时弹窗保持打开，方便复制 SQL 到查询标签页排查
- 演示模式连接为只读数据集，SQL 仅作预览、无法执行（弹窗内有醒目提示）

## 3. 执行 SQL

### 多标签页

- 顶部「+」或 **⌘/Ctrl + T** 新建查询标签页；双击标签名可重命名
- 每个标签页独立记忆：使用的连接、活动 Schema、SQL 内容、执行结果
- 标签页上的 **●** 表示有未保存的脚本修改

### 编写与运行

- 编辑器基于 CodeMirror 6：SQL 语法高亮、表名/关键字补全、多光标、搜索（⌘/Ctrl + F）
- 点击「**运行**」按钮或 **⌘/Ctrl + Enter** 执行：
  - **选中了部分语句** → 只运行选中的片段
  - 未选中 → 运行编辑器全部内容（多条语句按顺序执行）
- 「**美化**」按钮可一键美化 SQL（按分号切分多语句逐条格式化）
- **自动 LIMIT 保护**：运行查询类语句（SELECT 等）时，若未手写 `LIMIT`，会按编辑器右上角「行数上限」自动附加，页脚有「已自动附加 LIMIT」提示；已含 `LIMIT` 的语句不重复添加
- 运行中按钮变为「运行中…」，可继续编辑其他标签页

### 连接与 Schema

编辑器工具条上有两个下拉框：

- **连接**：当前标签页使用的数据库连接（可随时切换）
- **Schema**：活动库。未在 SQL 中写库名时，语句默认在该库执行（也可显式写 `schema.table`）

## 4. 结果面板

执行 SQL 后，底部结果区展示结果。

### 结果页签

- 每次执行生成一个结果页签，标签显示语句摘要与行数（失败显示「失败」）
- **鼠标悬停页签，点右侧 ×** 可关闭该页签
- **页签右键菜单**：复制 CSV / 复制 INSERT / 下载 CSV / 下载 INSERT / 关闭 / 关闭其他标签页 / 关闭全部
- 页签栏最右的「**清空结果**」一键清空当前标签页的所有结果
- 「**消息**」页签：汇总每次执行的语句、耗时、影响行数 / 错误信息

### 结果表格

- 表头两行：**字段名 + 类型缩写**；主键列带 **PK** 徽标；第二行显示字段的 **COMMENT 描述**（来自 `information_schema.COLUMNS`）
- 单元格内容过长自动截断，点击单元格可查看 / 复制完整内容
- **单元格右键菜单**：复制单元格值，或按当前行数据生成 SQL——「复制为 INSERT 语句」「复制为 UPDATE 语句」（可直接粘贴到编辑器执行）
- 底部信息条固定显示：**行数 · 耗时**，不随内容滚动
- 「下载 CSV」可将当前结果集导出为 CSV

### 调整高度

拖动编辑器与结果区之间的**分隔条**可调整结果区高度（双击场景：结果区默认约 45% 视口高）。

## 5. SQL 脚本

把常用 SQL 保存为脚本，避免重复粘贴。

- **保存**：**⌘/Ctrl + S** 或工具条「保存脚本」→ 输入脚本名称（首次保存需命名）
- **更新**：已保存过的脚本再次 ⌘/Ctrl + S 时，可选择「更新当前脚本」或「另存为新脚本」；修改未保存时标签名旁有 **●** 提示
- **重命名**：在左下角「脚本」面板中双击脚本名
- **打开**：在「脚本」面板中**双击**脚本打开；若该脚本已有打开的标签页，会直接切换过去，不会重复开新窗口
- **关闭保护**：关闭有未保存修改的脚本标签页时，会弹窗询问「保存并关闭 / 不保存 / 取消」，多个未保存脚本合并为一次确认
- **导出**：面板顶部「⬇」导出全部脚本；脚本行内「⬇」导出单个脚本，详见[第 7 节](#7-导出)
- **删除**：脚本行内「🗑」删除

> 脚本全部保存在本机（Web 模式 localStorage / 插件模式 chrome.storage），仅本机本浏览器可见。

## 6. 执行历史

左下角「**历史**」面板自动记录最近执行的 SQL（含连接、Schema、耗时、成功 / 失败状态）。点击任意一条即可在新查询标签页中回填重跑。

## 7. 导出

### 导出 SQL（表右键「导出 SQL（DDL + 数据）…」）

导出弹窗内可勾选：

| 选项 | 说明 |
| --- | --- |
| 包含 DDL | 输出 `SHOW CREATE TABLE` 的建表语句 |
| 前置 `DROP TABLE IF EXISTS` | 建表语句前加删表语句 |
| 包含数据 INSERT | 输出表数据（SELECT 全字段），上限 **50000 行**，超出会在标题下方提示 |
| `INSERT IGNORE` | 数据语句改写为 `INSERT IGNORE`，导入时跳过冲突行 |

底部按钮：

- **下载 CSV**：导出表数据 CSV
- **下载 SQL**：按当前选项生成 `.sql` 文件并**直接下载**
- **SQL预览**：打开预览弹窗（语法高亮），可复制全文或下载 `.sql`；预览**叠加**在导出弹窗上层，关闭预览后导出弹窗原样保留，可继续调整选项后再次预览或下载

### 查询结果导出

结果表格工具条的「下载 CSV」直接导出当前结果集。

### 导出保存的脚本

左下角「脚本」面板支持把已保存的脚本导出为 `.sql` 文件，方便备份、归档或在其他机器导入：

- **导出单个**：脚本行内「⬇」按钮 → 弹出保存对话框，可选择目录与文件名
- **导出全部**：面板顶部「⬇」按钮 → 选择目标目录，全部脚本一次性批量写入

导出的 `.sql` 文件头部自动附带来源注释，便于归档识别：

```sql
-- 导出自 MySQL Web Studio
-- 脚本: 用户查询
-- 关联连接: 本地开发
-- Schema: sales
-- 导出时间: 2026/10/19 15:30:00

SELECT * FROM orders;
```

说明：

- 文件名为脚本名安全化处理（去除文件系统非法字符）后加 `.sql` 后缀；写入目录时若与现有文件重名，自动追加 `-2`、`-3` 序号，不会覆盖已有文件
- **桌面客户端**：单脚本走系统保存对话框、导出全部走系统目录选择对话框，均可指定位置；**Web / 插件模式**：受浏览器沙箱限制，逐个下载到浏览器下载目录

### DDL 查看

表右键「查看 DDL」的弹窗同样支持复制与下载 `.ddl.sql`。

## 8. AI 助手（SQL AI）

顶栏「**SQL AI**」按钮（花瓣 logo）打开右侧 AI 助手面板。它是一个**浏览器端 Function Calling 智能体**：模型（OpenAI 兼容端点）由浏览器直连，负责理解意图与生成 SQL；所有数据库操作都通过本地工具回调执行，模型只收到查询结果的截断摘要。

### 打开与布局

- 顶栏「SQL AI」按钮打开 / `Esc` 收起；面板宽度可拖拽调整（300–720px）并持久化
- 输入区：`Enter` 发送、`Shift+Enter` 换行；`@` 唤起表名补全；`/` 唤起快捷指令
- AI 的每次工具调用以**折叠卡片**展示（工具名、SQL、耗时 / 行数），可展开查看

### 模型配置

首次使用点击面板头部「模型设置」（齿轮图标）：

- **端点三要素**：API 地址、模型名称、API Key，可从预设服务商一键填充（DeepSeek / OpenAI / Moonshot / 通义千问 / 豆包 / 智谱 / Ollama / 自定义 OpenAI 兼容端点）
- **高级参数**：temperature、maxTokens、请求超时（默认 60s）、减少动效
- **多套方案**：可保存多个模型方案（如「DeepSeek」与「GPT-4o」并存），面板头部下拉随时切换
- ⚠️ API Key 仅保存在本机，由浏览器直连模型服务（建议使用 HTTPS 端点），不经过任何中间服务器

### 会话管理

- 面板头部可新建 / 切换会话，时钟图标打开会话历史
- 新会话默认标题「**chat会话**」，发出首句话后自动以该句重命名；空会话不进入历史
- 会话上限 30 个，每会话消息上限 200 条，均持久化在本机
- 新打开（或切入）一个空会话时，会自动重查当前连接的 Schema 与表清单，刷新 AI 上下文

### 上下文注入

- AI 自动感知当前标签页的**连接与活动 Schema**（标签页未选连接时，回退到第一个已连接的连接）
- 输入 `@表名` 后，该表的**真实 DDL** 会作为附注注入对话（防止模型编造表结构）
- 斜杠快捷指令：

| 指令 | 作用 |
| --- | --- |
| `/explain` | 解释编辑器中的 SQL |
| `/optimize` | 优化编辑器中的 SQL |
| `/tables` | 介绍当前 Schema 的表 |
| `/fix` | 根据最近一次执行报错修复 SQL |
| `/clear` | 清空当前会话 |

### SQL 执行：风险分级 + 人工确认

AI 生成的 SQL 不会盲目执行——每条语句先经本地**风险分级**（纯前端判定，模型无法绕过）：

| 级别 | 类型 | 示例 | 默认行为 |
| --- | --- | --- | --- |
| L0 | 只读 | SELECT / SHOW / DESC / EXPLAIN | 自动执行（可在设置中关闭），自动附加 LIMIT |
| L1 | 数据变更 | INSERT / UPDATE / DELETE | 弹窗人工确认 |
| L2 | 结构变更 | CREATE / ALTER / DROP / TRUNCATE | 弹窗人工确认 |
| L3 | 服务器级 / 多语句 / 无法识别 | GRANT / KILL / LOAD DATA / SET GLOBAL | 弹窗人工确认 |

- 确认弹窗中可勾选「本次会话记住放行」（仅对 L0 只读生效）；「拒绝执行」会把结果告知 AI，由它调整方案

### SQL 代码块操作

AI 回复中的 SQL 代码块带工具条：**复制** / **插入编辑器** / **直接运行**（直接运行的结果进入底部结果区，AI 可继续解读）。

> 数据安全：模型配置与对话记录仅存本机；数据库操作复用既有 WS 桥接通道，工具结果截断后回传模型，完整数据仅在本机展示。产品设计详见 [AI 助手规划文档](ai/README.md)。

## 11. Chrome 插件模式

除 Web 方式外，本项目可打包为 **Chrome 插件（MV3）** 安装使用，功能与 Web 模式完全一致，数据跟随浏览器 Profile 保存。

### 构建与安装

```bash
npm run build:ext   # 构建产物输出到 dist/（静态前端 + manifest.json + sw.js）
```

1. 打开 Chrome，访问 `chrome://extensions`
2. 打开右上角「**开发者模式**」
3. 点击「**加载已解压的扩展程序**」，选择项目的 `dist/` 目录
4. 安装后点击工具栏中的插件图标，即在全屏标签页中打开客户端

### 启动桥接器

插件产物是纯静态前端（浏览器无法直连 MySQL TCP），需要单独运行本机桥接器：

```bash
npm run bridge   # 默认监听 5189 端口，可通过 MYSQL_BRIDGE_PORT 环境变量或命令行参数修改
```

插件模式下的连接，桥接地址留空即自动连接 `ws://localhost:5189/__mysql_bridge`；若自建了桥接服务，可在「高级选项」中手动填写（公网地址必须使用 `wss://`）。

### 与 Web 模式的差异

| 项 | Web 模式 | Chrome 插件模式 |
| --- | --- | --- |
| 打开方式 | `npm run dev` 启动的网页 | 工具栏插件图标（全屏标签页） |
| 桥接器 | 内嵌在 Vite dev server（与页面同端口） | 独立进程 `npm run bridge`（默认 5189） |
| 数据存储 | `localStorage` | `chrome.storage.local` |
| 连接 MySQL | 由 dev server 内嵌桥接器代理 | 由本机独立桥接器代理 |

> 卸载插件会清除 `chrome.storage.local` 中的全部数据（连接、脚本、历史等），重要脚本请提前导出备份。

## 12. 桌面客户端模式

除 Web 与插件方式外，本项目提供 **Electron 桌面客户端**（Mac / Windows / Linux）。数据通路最短——主进程内置 mysql2 直连 MySQL，**无需浏览器、无需任何桥接器**，也不依赖 Node 环境。

### 安装与打包

| 平台 | 命令 | 产物（输出到 `release/`） |
| --- | --- | --- |
| macOS | `npm run dist:mac` | dmg + zip（arm64 / x64） |
| Windows | `npm run dist:win` | nsis 安装器（x64，可选安装目录、桌面快捷方式） |
| Linux | `npm run dist:linux` | AppImage + deb（x64） |

- **未签名安装包**首次打开需手动放行：mac 右键「打开」，或「系统设置 → 隐私与安全性」中点「仍要打开」（顽固时终端执行 `xattr -cr "/Applications/MySQL Web Studio.app"`）；Windows SmartScreen 弹窗点「仍要运行」。详见 [FAQ Q11](#13-常见问题-faq)
- **正式分发签名**：mac 用 `npm run dist:mac:signed`（需配置 Apple 开发者证书三件套环境变量，签名 + 公证走 [electron-builder.signed.yml](../electron-builder.signed.yml)）；Windows 设 `CSC_LINK` 环境变量后 `dist:win` 自动签名
- 客户端内置**自动更新**（见下文），发布渠道默认指向 GitHub Releases `guonl/guonl-mysql-web-studio`

### 开发调试

```bash
npm run dev:desktop   # 起 Vite dev server → 就绪后自动拉起 Electron 窗口（HMR 生效）
```

- 端口被占用时可用 `PORT=5190 npm run dev:desktop` 换端口；加 `--strictPort` 则端口被占直接报错退出（不静默换端口）
- 调试主进程持久化时可用 `MWS_USER_DATA=/tmp/mws-test npm run dev:desktop` 把 userData 指到临时目录，避免污染正式数据
- 主进程日志（dev 模式）会打印 `app start · dev=true`，自动更新在开发模式下自动跳过

### 原生菜单与文件能力

| 菜单 | 项 | 说明 |
| --- | --- | --- |
| 文件 | 打开 SQL 文件（`⌘/Ctrl + O`） | 系统文件对话框选择 `.sql` / `.txt`（≤ 20MB），在新查询标签页打开 |
| 文件 | 导出当前 SQL（`Shift + ⌘/Ctrl + S`） | 把当前标签页 SQL 落到系统保存对话框 |
| 编辑 / 视图 / 窗口 | — | 标准剪贴板、重新加载、缩放、全屏等 |
| 帮助 | 检查更新 | 手动触发一次更新检查 |
| 帮助 | 源码仓库 / 打开日志目录 | 系统浏览器打开 GitHub 仓库 / 文件管理器打开日志目录 |

- **界面内所有下载**（导出 SQL、下载 CSV 等）统一走**系统保存对话框**，可选保存位置，不再落到浏览器下载目录
- **批量导出脚本**（脚本面板「导出全部」）走系统**目录选择**对话框，一次选目录、全部脚本直接写入所选目录（重名自动追加序号）
- **外部链接**（文档、AI 端点页面等）一律调用系统默认浏览器打开，不在应用内跳转
- AI 助手浏览器直连模型端点时如遇 CORS 限制，主进程会自动补齐响应头

### 自动更新

- 应用启动约 10 秒后**静默检查**更新（仅生产构建；开发模式自动跳过），发现新版本后台下载
- 下载完成后弹窗提示，可选择「立即重启安装」或「稍后」（下次启动生效）
- 也可随时通过菜单「帮助 → 检查更新」手动检查
- 默认更新源为 GitHub Releases；自建分发时设环境变量 `MWS_UPDATE_URL` 指向 generic 静态源即可覆盖

### 数据与日志位置

桌面客户端数据与 Web / 插件形态**各自独立、互不通用**：

| 数据 | 位置 |
| --- | --- |
| 连接 / 脚本 / 历史 / 偏好 | 应用内 `localStorage`（userData 下的 Local Storage） |
| 运行日志 | `userData/logs/main.log`（超 2MB 自动轮换为 `main.old.log`） |
| 窗口状态 | `userData/window-state.json`（尺寸、位置、最大化状态；跨显示器不可见时自动校正） |

`userData` 典型路径：macOS `~/Library/Application Support/MySQL Web Studio/`、Windows `%APPDATA%/MySQL Web Studio/`、Linux `~/.config/MySQL Web Studio/`；最直接的方式是菜单「**帮助 → 打开日志目录**」直达。

### 三形态差异总览

| 项 | Web 模式 | Chrome 插件模式 | 桌面客户端 |
| --- | --- | --- | --- |
| 打开方式 | `npm run dev` 启动的网页 | 工具栏插件图标 | 双击应用 |
| 连接 MySQL | dev server 内嵌桥接器代理 | 独立桥接器（5189）代理 | 主进程 mysql2 直连 |
| 数据存储 | `localStorage` | `chrome.storage.local` | 应用内 `localStorage`（userData） |
| 下载行为 | 浏览器下载目录 | 浏览器下载目录 | 系统保存对话框 |
| 自动更新 | 随部署更新 | 手动重新加载插件 | 内置 electron-updater |
| 适用场景 | 团队内网 / 临时使用 | 浏览器常驻 | 日常主力工具 |

## 13. 常见问题 FAQ

**Q1：提示「WebSocket 桥接连接失败」？**
A：说明页面连不上内置桥接器。确认 dev server 正在运行（`npm run dev`）；若手动填过桥接地址，请清空「高级选项」中的桥接地址让其自动生成。

**Q2：提示 `Access denied ... (using password: NO)`？**
A：密码没有随连接发送。编辑该连接，确认密码已填写；未勾选「记住密码」时，刷新页面后需重新输入密码。

**Q3：提示认证插件不支持（如 `caching_sha2_password` 报错）？**
A：桥接器基于 mysql2，支持 MySQL 8 默认的 `caching_sha2_password`。若使用 `sha256_password` 或开启了特殊 SSL 策略，请检查服务端认证配置。

**Q4：连接超时？**
A：确认 MySQL 服务器地址 / 端口正确、网络可达；云数据库请检查 IP 白名单是否放行了**你本机的公网出口 IP**（不是浏览器 IP，是运行 dev server 的机器的出口 IP）。

**Q5：结果表头没有显示 COMMENT？**
A：COMMENT 通过 `information_schema.COLUMNS` 补齐获取；若连接账号无权限读取 `information_schema`，注释列为空但不影响结果。

**Q6：导出的 INSERT 只有 50000 行？**
A：数据导出设有安全上限（防止超大表拖垮浏览器），达到上限时会在导出弹窗标题下提示「已达导出上限」。超大表建议使用 `mysqldump` 等专业工具。

**Q7：刷新后连接还在但密码没了？**
A：未勾选「记住密码」的连接只保留连接信息，密码按设计不落盘，重新输入即可。

**Q8：可以部署到服务器给团队用吗？**
A：`npm run build` 的产物是纯静态前端，不含桥接器，直接部署**无法连库**。团队使用需要自行实现带鉴权的独立桥接服务，并在「高级选项」中填写其地址。详见 [架构说明](architecture.md)。

**Q9：插件模式下提示「WebSocket 桥接连接失败」？**
A：确认已在终端运行 `npm run bridge` 启动独立桥接器（默认端口 5189，可用 `curl http://127.0.0.1:5189/` 做健康检查）；若手动填过桥接地址，请清空「高级选项」让其自动生成；远程桥接必须使用 `wss://` 地址。

**Q10：AI 助手不回复 / 报错连不上模型？**
A：在面板「模型设置」中检查 API 地址、模型名称与 API Key 三要素是否匹配（可从预设服务商一键填充，避免手误）；确认本机网络可访问该服务商端点（部分服务商需要代理），必要时调大请求超时（默认 60s）。AI 的数据库操作走本地桥接通道，与模型连通性无关——若左侧树能正常查库而 AI 无回复，问题出在模型端配置。

**Q11：mac 打开桌面客户端提示「无法验证开发者」或「已损坏」？**
A：安装包未做签名 / 公证，macOS Gatekeeper 默认拦截。依次尝试：① 右键 App 点「打开」；② 「系统设置 → 隐私与安全性」底部点「仍要打开」；③ 仍报「已损坏」时在终端执行 `xattr -cr "/Applications/MySQL Web Studio.app"` 清除隔离标记后重新打开。Windows 首次运行若遇 SmartScreen 蓝色弹窗，点「更多信息 → 仍要运行」即可。正式分发建议签名 + 公证（见[第 12 节](#12-桌面客户端模式)）。

**Q12：桌面客户端的数据和日志放在哪？**
A：都在应用 userData 目录下——连接 / 脚本 / 历史存在应用内 `localStorage`，日志在 `logs/main.log`（超 2MB 自动轮换），窗口状态在 `window-state.json`。macOS 典型路径 `~/Library/Application Support/MySQL Web Studio/`，Windows `%APPDATA%/MySQL Web Studio/`，可直接点菜单「帮助 → 打开日志目录」直达。注意三种形态（Web / 插件 / 桌面）数据**各自独立、互不通用**，迁移数据需重新录入或导出脚本备份。

**Q13：桌面客户端「检查更新」提示已是最新 / 检查失败？**
A：「已是最新」说明当前 GitHub Releases 上没有比本机版本号更高的发布——更新检查以 Release 的最新版本为准，本地自行构建的版本不会触发更新。「检查失败」多为网络无法访问 GitHub（国内网络常见，可配置代理后重试）。自建分发渠道时，设环境变量 `MWS_UPDATE_URL` 指向 generic 静态源（放 `latest.yml` 与安装包）即可覆盖默认更新源。
